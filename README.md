## ❓ What is Collaborative Filtering?

<div align="center">
  <img src="https://github.com/MarpakaPradeepSai/Book-Recommendation-System/blob/main/Data/Images%20&%20GIF/CF2.webp?raw=true" alt="Collaborative Filtering" width="600"/>
</div>

**Collaborative filtering** is a technique used by recommender systems to predict a user's interests by collecting preferences from a broader user base. 

This project specifically utilizes **Item-Based Collaborative Filtering**, which recommends items to a target user based on the similarities between the items themselves. If User A likes *Harry Potter 1*, and the system identifies that *Harry Potter 1* is mathematically similar to *Harry Potter 2* (because users who read the first almost always read the second), it will recommend the latter.

**Advantages:**
- 🎯 **User-Centric:** Adapts to complex, nuanced user behaviors.
- 🚫 **No Item Metadata Needed:** Doesn't rely on tags or genres.
- ✨ **Serendipity:** Helps users discover unexpected but highly relevant books.

## 🔬 Methodology & Data Processing

### 🧹 1. Data Cleaning
- **Handling Outliers:** Detected and removed extreme outliers in the `Age` demographic using the IQR (Interquartile Range) method to ensure clean demographic analysis.
- **Type Casting:** Cleaned invalid string entries in the `Year-Of-Publication` column and converted it to integer formats.
- **Missing Values:** Dropped rows with null `Book-Title` entries to ensure the final UI displays complete information.

### ⚖️ 2. Sparsity Reduction (The "Cold Start" Fix)
Recommendation matrices are notoriously sparse. To ensure high-quality recommendations and computational efficiency, the dataset was rigorously filtered:
1. **Active Users Only:** Filtered out users who rated fewer than **100 books** (resulting in `filtered_df`).
2. **Popular Books Only:** Filtered out books that received fewer than **50 ratings** (resulting in `final_filtered_df` — the working dataset for all models).
3. **Result:** `final_filtered_df` contains **96,314 rows** across **1,072 unique books** and **1,552 active users**, ready for mathematical similarity calculations.

### 🔑 3. Explicit Ratings Separation (Key Optimization)
A critical optimization in this project is the strict separation of **explicit ratings** from **implicit interactions**:

- The raw ratings data contains two types of entries: **explicit ratings (1–10)**, where users actively scored a book, and **implicit interactions (rating = 0)**, which indicate the user touched the book but left no numerical score.
- A rating of `0` is **not** a bad rating — it is missing data and must not be treated as one mathematically.
- For all model training and similarity calculations, a dedicated `explicit_ratings_df` is created by filtering `final_filtered_df` to include **only rows where `rating > 0`**.
- The book-user pivot matrix (`book_user_mat`) is then built from this `explicit_ratings_df`, ensuring that `fillna(0)` only fills **truly unobserved pairs** — not masking implicit interactions as zero scores.
- During recommendation generation, the **full interaction history** (including implicit 0s) is used to block already-seen books from being re-recommended to a user.

## ⚔️ Model Architecture & Evaluation

Three distinct approaches were evaluated using a **unified evaluation framework** on a consistent 80/20 train-test split (`random_state=42`). All models were evaluated with `K=10` and a `Relevance Threshold=5` (ratings ≥ 5 considered relevant). Rating prediction metrics (MAE, RMSE) were computed **only on explicit ratings (> 0)** in the test set.

### 🚀 1. Cosine Similarity (Deployed Model)
- **Mechanism:** Separates `explicit_ratings_df` (ratings 1–10) from the full dataset to build the book-user pivot matrix. Calculates the cosine of the angle between book vectors in user space. For **item-to-item recommendations**, the top similar books are returned directly from the similarity matrix. For **personalized user recommendations**, candidate scores are aggregated across all books in the user's full interaction history (including 0s for history tracking) via the cosine similarity matrix.
- **Why it was chosen:** Highly efficient, deterministic, and scales beautifully within Streamlit. Naturally normalizes for users who rate books more generously. Produces identical or superior ranking metrics to kNN with significantly lower complexity.
- **Evaluation Metrics:**
  - **MAE:** 1.0577
  - **RMSE:** 1.6181
  - **Precision@10:** 0.0326
  - **Recall@10:** 0.0868
  - **NDCG@10:** 0.1323
  - **HitRate@10:** 0.2293
  - **Coverage:** 0.7397
  - **Rating predictions evaluated:** 2,233 over 1,571 users

### 🤖 2. k-Nearest Neighbors (kNN)
- **Mechanism:** Also uses `explicit_ratings_df` to build the item-user pivot table. Utilizes `sklearn.neighbors.NearestNeighbors` with `metric='cosine'` and `algorithm='brute'`. For personalized recommendations, KNN neighborhoods are queried per book in the user's history, and similarity scores are aggregated as candidates. Implicit 0s in the user's full history are used to block re-recommendations.
- **Evaluation Metrics:**
  - **MAE:** 1.0577
  - **RMSE:** 1.6181
  - **Precision@10:** 0.0326
  - **Recall@10:** 0.0868
  - **NDCG@10:** 0.1323
  - **HitRate@10:** 0.2293
  - **Coverage:** 0.7388
  - **Rating predictions evaluated:** 2,233 over 1,571 users

### 📊 3. K-Means Clustering
- **Mechanism:** Uses `explicit_ratings_df` to construct a user-item pivot table (indexed by `userId`, columns are book titles). Books are clustered using KMeans in this user-rating vector space. For recommendations, books in the same cluster as a user's history items are ranked by cosine similarity.
- **Optimization:** Used the **Silhouette Score** to find the optimal number of clusters across k=2 to 20. The optimal was found at **k=2** with a Silhouette Score of **0.3588**.
- **Evaluation Metrics:**
  - **MAE:** 1.1627
  - **RMSE:** 1.5868
  - **Precision@10:** 0.0258
  - **Recall@10:** 0.0712
  - **NDCG@10:** 0.1123
  - **HitRate@10:** 0.2003
  - **Coverage:** 0.6017
  - **Rating predictions evaluated:** 5,268 over 1,571 users
> **Verdict:** Hard-clustering limits the nuanced, ranked recommendations required for a consumer-facing app. With only 2 clusters covering the entire catalog, the candidate pool becomes too broad and less precise compared to continuous similarity scoring used by Cosine/kNN approaches.

### 📉 2. Rating Distributions & Engagement

*   **The Implicit Majority:** Over **647,294** interactions were implicit (a rating of 0, meaning the user interacted with the book but didn't leave a 1–10 score). These are tracked for history but **excluded from similarity calculations**.
*   **Positivity Bias:** Among explicit ratings (1–10), **8 is the most common score**, indicating users are more likely to rate books they actually enjoyed.
*   **The "Wild Animus" Anomaly:** The book *Wild Animus* had the highest total occurrences (2,502) but overwhelmingly dominated the **"1-star"** rating category. High visibility does not equal high satisfaction!

## 🛠️ Installation & Usage

### Prerequisites

- Python 3.8+
- pip package manager

### Local Setup Instructions

1. **Clone the repository**
   ```bash
   git clone https://github.com/MarpakaPradeepSai/Book-Recommendation-System.git
   cd Book-Recommendation-System
   ```

2. **Create and activate a virtual environment (Recommended)**
   ```bash
   python -m venv venv
   source venv/bin/activate  # On Windows: venv\Scripts\activate
   ```

3. **Install required dependencies**
   ```bash
   pip install streamlit pandas numpy scikit-learn huggingface_hub
   ```

4. **Run the Streamlit Application**
   ```bash
   streamlit run app.py
   ```

> **Note on Data Loading:** The application is configured to automatically download the pre-processed pivot tables and datasets directly from Hugging Face (`IamPradeep/BRS_DATA`). You do not need to download the CSV files manually!
